# Защищённая панель владельца Vibely

Панель находится по адресу `/owner.html`. Она использует Supabase Auth и серверную роль профиля `owner` или `admin`. В исходном коде нет отдельно��о пароля-владельца и не должно быть: пароль хранится и проверяется провайдером Auth, а права подтверждает Postgres RLS.

## Установка

1. Сначала настрой Supabase и выполни `supabase/schema.sql`.
2. В Supabase SQL Editor выполни `supabase/owner-moderation.sql`.
3. Настрой `supabase-config.js` клиентскими Project URL и publishable/anon key. Никогда не размещай `service_role` key в браузере или репозитории.
4. Зарегистрируй свой личный аккаунт через приложение и подтверди email.
5. В SQL Editor назначь владельцем **только собственный подтверждённый аккаунт**, подставив его email:

```sql
update public.profiles p
set role = 'owner'
from auth.users u
where p.id = u.id and u.email = 'YOUR_VERIFIED_EMAIL';
```

6. Открой `owner.html` на опубликованном сайте и войди тем же аккаунтом. Остальные пользователи без роли `owner`/`admin` не попадут в панель.

Не используй пароль, отправленный в переп��ске, как секретный пароль владельца: любой пароль, опубликованный в чате, следует считать раскрытым и сменить в Supabase Auth. Не добавляй пароли в HTML, JavaScript, SQL в репозитории, URL, логи или GitHub Secrets для браузерного приложения.

## Возможности MVP-панели

- Просмотр последних 50 профилей и публикаций, счётчики.
- Обработка жалоб: просмотр, закрытие, удаление связанного поста.
- Скрытие/возврат публикации и удаление контента.
- RLS ограничивает доступ; роль нельзя повысить через обычный клиентский API.

Удаление поста не удаляет автоматически объект из Storage: очистку медиа лучше делать отдельной серверной Edge Function после проверки владельца объекта. Для публичного запуска дополнительно нужны CAPTCHA/rate limits, политика модерации, резервные копии и защищённая процедура восстановления аккаунта.
